# Codex 子代理契約

日常預設單一主代理；只有子任務互不依賴、可獨立驗收且收益超過協調成本，才使用 Codex 子代理。模型與推理設定由目前執行環境及使用者選擇控制，本文件不維護模型路由表。

## 邊界

- 本工作流上限為 **2 個同時工作的子代理**，不含主代理；這是使用者核准的建議值，不是官方限制。平台與有效設定更嚴格時採較嚴格限制。
- 不同執行者不得並行修改相同檔案或責任區；禁止子代理遞迴派工。
- 一批一主題，實作通常 2–3 檔；唯讀審查最多 4 檔。跨層依賴拆成連續批次，不用同時改同檔解決。
- 主代理保留核心規則、FSM、AI、線上同步、高風險跨模組決策及最終整合責任。
- 不使用 OpenCode Go；取消範圍及歷史材料界線見根目錄 `AGENTS.md`。

## 每次分派必備

```text
唯一子任務與不包含事項：
必要上下文、已確認證據及待解問題：
允許讀取的路徑：
允許修改的路徑／讀寫權／唯一檔案所有權：
其他執行者的責任區與既有修改保護：
完成條件與必要驗證：
停止條件、最多一次有依據的恢復：
交付：結論、修改位置、命令／環境／結束碼／結果、未確認事項。
禁止：擴大範圍、覆寫其他人修改、遞迴派工、自行 stage／commit／push。
```

## 整合與恢復

- 主代理核對關鍵結論、diff 與測試證據，不重新做完子代理整段探索；要複查時指出具體疑點。
- 測試依 [驗證分級](verification-levels.md)，不因派工縮小而免除主線整合門檻。
- 首次停滯可依證據縮小後恢復一次，再次停滯主代理接手。發生停滯時才讀 [停滯與交接協定](../../../../docs/subagent-stall-handoff-protocol.md)。
