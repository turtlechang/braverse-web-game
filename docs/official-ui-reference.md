## 整合原則

- 最大化桌面版採「桌墊聚焦」方向：左側只保留窄型五階段列，未啟用階段降低對比，目前階段與「下一步」維持最高辨識度。
- 不使用固定右側 HUD。重置、牌組清單與暫停資訊縮成右上角圖示按鈕；牌組配對、AI 動作數與 20 場驗證移入暫停視窗。
- 對手與我方皆有獨立手牌、支援區、戰鬥區、休息區、牌庫、場景區與棄牌區；每方場地固定採戰鬥區 55%、支援區 45%。
- 戰鬥卡靠近中央分隔列；我方支援卡由左向右、對手支援卡由右向左排列，並優先維持卡面可辨識尺寸。
- 對手手牌配置於對手場地上方；玩家手牌配置於玩家場地下方，靠近右側牌庫。所有卡牌以上方中央為共同支點，向下扇形展開；畫面由左至右依序覆蓋，右側卡牌位於較高層級；六張角度保持 -25/-15/-5/5/15/25 度、牌背內容 180 度，不與牌庫、場景、棄牌、支援或戰鬥卡重疊；支援區左界安全限制保持不變，正角度卡向左外伸不越界。1538×578 左界 0.96px，600×338 與 1920×1080 亦未越界且無捲軸、無 console error。牌背內容以 CSS 旋轉180度。
- 對手名稱與先後攻資訊附著於對手戰鬥區左下角；我方名稱牌維持戰鬥區左上角。
- 對手支援區位於戰鬥區上方，我方支援區位於戰鬥區下方；玩家名稱、先後攻與手牌數縮成附著於戰鬥區邊緣的名稱牌。
- 牌庫、場景與休息區以桌面牌堆和數字徽章呈現，點擊後在牌堆旁開啟浮層；棄牌區與完整牌組仍使用大型視窗。
- 手牌預設只呈現卡牌。合法卡被選取後才抬升並顯示唯一主要動作與詳情，點擊空白處或按 `Escape` 取消。
- 攻擊付款、目標選擇、AI 思考與一般對局訊息集中在中央分隔列，避免玩家在左右資訊區來回搜尋。
- 選卡、Refresh、替補與對局結果使用暗幕中央視窗；使用官方紅色、黃色與綠色起始牌組 metadata 中的圖片 URL 呈現牌面。
- 不把整張官方截圖當作背景，也不將來源截圖提交至 repository。

## 響應式調整

官方截圖以 16:9 桌面為主；專案畫面則使用滿版 viewport，不再限制整體 16:9。專案在 900px 以下窄畫布將階段導覽改為頂部橫列，
對局資訊與操作改為底部橫列，中央牌桌取得完整寬度；戰鬥區保留上下關係，
手牌縮小牌面與扇形間距，並限制在中央欄內，不得遮蔽左右資源區。
桌面版對戰桌固定等分為對手場地、中線與玩家場地；雙方手牌配置在各自
戰鬥區邊緣，不得遮蔽支援區。卡牌橫置僅套用視覺旋轉，不得改變戰鬥區、
支援區、玩家場地或整體滿版畫布尺寸。

`game-shell` 是具名 size container。一般桌面維持完整尺寸；當容器高度低於
800px、720px、620px 或 400px、寬度低於 1200px 或 900px 時，以 Container Queries
切換 HUD、場地、卡牌與手牌的緊湊尺寸，最低支援 600x338。這種方式保留 DOM
文字的瀏覽器原生渲染，不使用整頁
`transform: scale()` 或 JavaScript 動態修改根字級。專案目前沒有 Canvas
遊戲畫面，因此不套用 Canvas DPR scaling；行動裝置 safe-area 會在正式支援
手機版時另外處理。
