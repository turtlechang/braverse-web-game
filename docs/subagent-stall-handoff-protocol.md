# 子代理停滯與交接協定

本文件只在 Codex 子代理逾時、重複無進度或交接時使用。派工邊界與唯一契約見 [派工契約](../.agents/skills/braverse-workflow/references/delegation-template.md)，不在此複製。

## 停滯判定

只描述計畫而無可檢查結果、重複回覆無新證據或逾時，視為一次停滯。先核對工作樹、diff 與已有測試輸出，不能把代理自稱完成當成證據，也不能把環境／權限失敗當成產品缺陷。

## 恢復與接手

1. 讀取目前 Git 狀態及任務檔案差異，辨識已完成、未完成及真正阻塞。
2. 已有且仍適用的驗證直接重用；不足時才執行最小相關檢查，完整門檻仍依 [驗證分級](../.agents/skills/braverse-workflow/references/verification-levels.md)。
3. 首次停滯可依新證據縮小任務，**最多恢復一次**。
4. 再次停滯由主代理接手可完成部分，不再重派相同任務；缺少授權、外部資料、環境或資源時只停受影響部分，完成其他獨立工作。

若平台提供正式 goal 狀態工具，依該工具當時的規範使用；不把子代理接手門檻等同於整體目標 blocked，也不另在文件維護工具計數規則。

## 交接記錄

沿用當前對話、任務報告或短計畫，記錄：

- 子任務與檔案所有權、已完成／未完成範圍。
- 最後有效的 diff、命令、環境、結束碼、成功或失敗證據。
- 阻塞來源、接手者、下一個具體動作及需要重跑的檢查。

不在本協定累積任務日誌。OpenCode Go 備援已取消，其服務檢查、推理、session 恢復與派工流程不再適用。
