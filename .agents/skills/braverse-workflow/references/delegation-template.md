# OpenCode Go 與 Subagent 派工模板

本專案預設由 Codex 做需求裁切、規則判定與最終審查；可可靠外包的實作、文件更新與唯讀審查優先派給 OpenCode Go。詳細模型路由、沙箱網路處理與 review-fast agent 設定見 `../../develop-braverse/references/delegation.md`。

## 派工原則

- 一個子任務只派一次；結果可用就整合，不平行重複耗用。
- 提供最小但足夠的檔案清單、修改邊界與驗收標準。
- 只讀審查最多聚焦 4 個檔案；跨模組審查拆成多個小派工。
- OpenCode Go 使用外部 HTTPS API；在受限 Codex 環境中第一次呼叫就使用核准的外部網路權限。
- 若 API 回覆帳務、授權或連線問題，先回報狀態，不把它誤判為模型推理失敗。

## 唯讀審查提示

```text
請唯讀審查，不要修改、stage、commit 或呼叫網路。

範圍：
- 檔案：
- 目標：

請依嚴重度列出：
1. 行為錯誤或回歸風險
2. 缺少測試或驗證
3. 安全或提交風險
4. 未確認事項
```

## 實作提示

```text
請直接修改，但不要 stage 或 commit。

任務：
必讀檔案：
允許修改：
不可修改：
驗收標準：
需執行驗證：

請回覆：修改檔案、驗證結果、風險與未確認事項。
```
