# 藍紫 AI 對黑續作：敗因、修正與驗證

本報告比較先前的 Lv.5 產品基準與本次修正；綠色沿用 v36.3，黃色、紅色及黑色均以當時已採用的策略為基準。分析中的對局是遊戲引擎模擬，不代表實際比賽勝率。

最新狀態：r16 噴牌必要門檻未增勝，已拒絕；r17 修正資源歸屬、終盤干擾與 EXTRA 順序，並修復 P-135 印刷技能費用。最近完整獨立全矩陣仍為未通過的 r14；新版候選程式尚未採用或提交。文件提交不代表候選程式已採用，下文各輪「未 commit」指當輪候選程式。

## r17 紫色噴牌、控制與 P 卡（本輪驗證完成，未通過採用門檻）

範圍延續正式 BS1～BS12 與 P 紫色卡，不把能力結構覆蓋當成所有牌型都已完成對局驗收。沿用原門檻、綠色 v36.3 與其他色基準；RAM 啟動低於 70%、達 74% 中止，未提高使用者的 75% 上限。產物入口 `output/ai-purple-mill-20261030-r17/`。

### 本輪修補

1. **分清己方與對手資源。** opt-in 紫色模型將對手棄牌／手牌門檻標成 `opponent-trash`／`opponent-hand`。P-135 自磨不能充當 BS9-097 的對手棄牌門檻，己方抽牌也不能充當 BS12-078 的對手手牌門檻；BS9-100 的對手噴牌才可提供對手棄牌 setup。三個原先失敗的組合測試已轉為通過。預設模型、藍色原分類不改。
2. **修補搜尋中斷造成的估值落差。** 合法技能產生強制對手棄牌待選時，搜尋尚未看到對手手牌減少，也看不到後續結束階段。僅紫色 Lv.5 MAIN 能力候選，按公開且不受卡面限制的待棄張數，每張最多計 6；不猜棄哪張、不計尚未發生的棄牌觸發。只有付款後原防守仍可支付，才計相同防守保留值。真實 1066 父案例恢復 BS9-102 啟動，待棄 1 張、防守保留 42，未消耗攻擊支援。
3. **把終盤順序套在實際根節點。** 雙方 Break 至少 7、紫色 EXTRA 需要棄戰鬥區素材，且有合法可結算的對手手牌干擾時，先解干擾，避免只撤去付款預覽卻仍給未付款 EXTRA 場面分。公開可達 Break 勝利的 EXTRA 例外仍保留；只限目前 MAIN 根節點，不能洩漏到支援階段選牌。
4. **P-135 的印刷費用修補。** [官方原圖](https://cookierunbraverse.com/data/en_storage/svAXCh3Gf8Z_QexkGflVMA.webp)確認 Black Forest Cookie 的 Once 啟動只有己方噴 2，沒有支付 2HP。移除轉接層錯加的 `hpToTrash`，保留印刷 LV2／4HP／PPP 普通 3。以完整實體 60 張牌表經真正開局指令建立場面，3 項測試先失敗再通過，涵蓋零支援可發動、HP 不減、牌庫減 2、棄牌增 2、不可重複 Once 與輸入不變。strict 1 verified／0 needs-review／0 blocked。攻擊 Then 的完整可選支付語意與線上逐卡流程未於本輪驗收，不能由 strict 或技能測試推稱整張卡完整通過。

錯誤 HP 費用版本的 P-135 試驗撤回作為實體策略證據，只保留舊 runtime 診斷。修費用後，以相同已開封 P 測試構築重播 28 組，原錯費用 5／28、修費用 4／28，不能宣稱規則修補提高勝率。這批採固定搜尋時鐘，只有機制／終局重播證據，不當作正式勝率或效能驗收；觀察到 21 場 P-135 登場、7 場 P-145 登場與一次 Refresh 免 Break，未再找到原錯費用下的自願致命 Refresh。

外部策略參考另查到[官方賽事訪談](https://www.cookierunbraverse.com.tw/post/%E8%96%91%E9%A4%85%E4%BA%BA%E5%B0%8D%E6%88%B0%E5%8D%A1%E7%89%8C-braverse-%E6%98%9F%E7%90%83%E4%BA%A4%E9%8B%92%E6%88%B0-%E8%8A%B1%E7%B5%AE%E5%A0%B1%E5%B0%8E-1)：純紫選手談到把對手餅乾送棄牌後搭配 BONUS 錢幣抽牌施壓。這提供「對手棄牌＋後續資源」的測試方向，不是現代卡池的勝率證明，也不能直接把己方自磨當成同一 combo。使用免費公開來源，未啟用付費影片畫面分析。

## r16 紫色噴牌與 BS1～BS12／P（未通過）

目前順序為：舊父局面定位 → 最小評分修補 → 舊樣本開發對照 → 技術驗證與未開封樣本 → 完整護欄與提交門檻。使用同一份報告追蹤；產物入口 `output/ai-purple-mill-20261030-r16/`，來源凍結為 r15 `development-v5`。

### 敗因與決策調整

- 重新逐指令檢查全部 31 個 BS9-098 合法機會，沒有一個可以單次耗盡對手牌庫，對手最少仍有 4 張；18 個同時有合法攻擊。犧牲健康的 Latte 換三張噴牌不必然有利，因此「零發動」不能直接當成 31 次決策錯誤，也不強制提高發動率。
- 真實父案例 748 的非致命 Refresh，原本總分從 204 降成 188：接近牌庫耗盡的 36 分高於 Refresh 增加一級 Break 的 20 分，產生反向誘因。改成每個必付 Cookie 的接近壓力最多 18，修後同一對局節點為 186→188；這只是同局面評分修正，不是新增勝局。
- 紫色 Lv.5 MAIN 能力若實際進入對手 Refresh，且原本公開棄牌中的 Cookie 已足以支付，依公開被動計算最低 Break 代價。到達 Break 上限者優先於一般相對場面收益；不讀本次未知牌庫噴出的卡面，也不跨越較高優先待選決策推論必勝。未強制 Refresh 或公開證據不足時不加此分。
- BS9-096 的己方 Refresh 保護及 BS9-111 的對手兩張 Refresh 代價納入公開噴牌風險；BS12-082 的道具棄牌限制納入控制能力模型。新分類仍由 MAIN 根決策 opt-in，預設模型保持原樣。
- BS9-106／107／108 的來源限定棄牌觸發，模型保留 `hand-to-trash-by-effect` 與印刷來源名；一般啟動、支付代價棄牌均不當成已觸發，也不形成可立即兌現的 MAIN Combo。實際事件仍由原規則引擎處理，未改卡文或觸發規則。
- 曾隔離測試把未準備 EXTRA 前的棄牌干擾時點擴大到己方 Break 6／對手 Break 9，89 組開發配對沒有增加 BS9 噴牌勝場，也沒恢復黑色反向護欄 29；未套用該門檻修改。首次分歧仍只是定位線索，不稱為唯一敗因。
