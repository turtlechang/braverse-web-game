## 整合原則

- 採用固定左側階段導覽、中央上下戰鬥區、右側牌庫／場景區。
- 對手與我方皆有獨立手牌、支援區、戰鬥區、休息區、牌庫、場景區與棄牌區。
- 對手手牌在頂部背面扇形排列；我方手牌在右下正面扇形排列。
- 對手支援區位於戰鬥區上方，我方支援區位於戰鬥區下方。
- 被擊倒餅乾在休息區正面疊放，並顯示休息區等級總和。
- 目前階段使用高對比色與箭頭提示，主要操作固定在階段導覽下方。
- 選卡、Refresh、替補與對局結果使用暗幕中央視窗。
- 使用官方紅色、黃色與綠色起始牌組 metadata 中的圖片 URL 呈現牌面。
- 不把整張官方截圖當作背景，也不將來源截圖提交至 repository。

## 響應式調整

官方截圖以 16:9 桌面為主。專案在 900px 以下窄畫布將階段導覽改為頂部橫列，
對局資訊與操作改為底部橫列，中央牌桌取得完整寬度；戰鬥區保留上下關係，
手牌縮小牌面與扇形間距，並限制在中央欄內，不得遮蔽左右資源區。
桌面版對戰桌固定等分為對手場地、中線與玩家場地；雙方手牌配置在各自
戰鬥區範圍內，不得遮蔽支援區。卡牌橫置僅套用視覺旋轉，不得改變戰鬥區、
支援區、玩家場地或整體 16:9 畫布尺寸。

`game-shell` 是具名 size container。一般桌面維持完整尺寸；當容器高度低於
720px、620px 或 400px、寬度低於 1200px 或 900px 時，以 Container Queries
切換 HUD、場地、卡牌與手牌的緊湊尺寸，最低支援 600x338。這種方式保留 DOM
文字的瀏覽器原生渲染，不使用整頁
`transform: scale()` 或 JavaScript 動態修改根字級。專案目前沒有 Canvas
遊戲畫面，因此不套用 Canvas DPR scaling；行動裝置 safe-area 會在正式支援
手機版時另外處理。
