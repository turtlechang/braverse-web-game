# 子代理停滯與交接協定

本文件是 Braverse 的子代理工作規範，目標是讓每次派工都能小步完成、可驗證、可接手。Codex 保留需求裁切、規則裁決、跨模組整合與最終驗收責任。

## 1. 批次切分

- 每個批次只處理一個主題，通常限制在 2–3 個檔案。
- 資料層、狀態機、UI 與輸入控制不得在同一批次混合修改；需要跨層時拆成連續批次。
- 同一子任務只派一次，不平行派相同範圍，也不讓子代理自行再派代理。
- 唯讀審查最多 4 個檔案；實作任務必須列出允許修改與不可修改範圍。

## 2. 派工契約

每次派工都要包含：

1. 目標與不包含事項。
2. 明確檔案清單與驗收條件。
3. 必須執行的最小驗證指令。
4. 回覆格式：修改檔案、驗證結果、風險、未確認事項。

子代理不得自行 `stage`、`commit`、`push` 或擴大範圍。Codex 會檢查 diff 後統一整合。

## 3. 小步驗證

- 每完成一個小功能先跑對應的單元測試或 lint，不要累積到整個批次結束才第一次驗證。
- 若修改規則或 AI，先跑受影響測試，再由 Codex 決定是否跑完整回歸。
- 代理回覆的「已完成」不視為證據；恢復或接手時以工作樹、diff、測試輸出與建置結果為準。

## 4. 停滯判定與恢復

若子代理逾時、重複回覆無進度、只描述計畫而沒有可檢查結果，視為一次停滯：

1. 先讀 `git status --short --branch`、`git diff --stat`，確認磁碟上的實際成果。
2. 執行最小相關測試，辨識是未完成、測試失敗或環境／授權問題。
3. 只恢復一次，將剩餘工作縮成一個可在單次派工完成的明確任務。
4. 若同一子任務連續兩次恢復仍停滯，Codex 直接接手剩餘的膠水程式或改派更適合的模型；不再無限重試。

「子代理停滯兩次」是工作流接手門檻，不等同於整體目標 blocked。整體目標只有在同一外部阻塞連續三個目標回合都無法前進時，才依系統規範標記 blocked。

## 5. 交接記錄

每次停滯或接手都記錄：

- 子任務名稱與範圍。
- 已修改檔案與目前 diff。
- 最後一個成功指令及失敗訊息。
- 下一個最小可執行步驟。
- 接手者與是否需要重新驗證。

這份記錄可放在 Codex 回覆、工作計畫或本文件的更新日誌，不把未證實的代理敘述當成完成證據。

## 6. OpenCode Go 同步規則

OpenCode Go 使用與 Codex 子代理相同的批次、驗證與停滯門檻。派工前先確認 `scripts/opencode-go.cmd --preflight`；需要確認推理服務時才加 `--check-inference`，避免每個微任務都消耗額度。

錯誤處理以證據為準：

- `token=0` 加上連線拒絕、session 遺失或受限環境訊息，標記為環境問題，不得回報成「沒有額度」。
- 只有結構化 provider code 或 HTTP 402 才能宣稱 quota／billing；純文字 quota、credit、billing 訊息一律視為未驗證。
- 可重試錯誤（網路、rate limit、timeout）最多依派工契約重試一次；auth、權限、模型不存在、未驗證錯誤先停止並交給 Codex 判斷。
- OpenCode Go 完成後仍需由 Codex 檢查工作樹、diff、測試與 CI 狀態，再決定是否整合或提交。
