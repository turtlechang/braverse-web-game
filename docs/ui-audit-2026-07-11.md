# UI 審查報告（UI Audit）

日期：2026-07-11（本報告為當日稍早的快照）。審查基準：本機 `npm run dev` 啟動後於 1280×720 視窗截圖觀察。以下每個面向明確區分「已觀察（本機截圖）」與「後續假設（尚待確認/補強）」。

> **狀態更新（2026-07-11 稍晚）**：本報告 §1、§5 標示的 P0 項目已於同日修正並實機驗證，詳見各節「已解決」註記與 [docs/ui-reference/02-main-menu-wireframe.md](ui-reference/02-main-menu-wireframe.md)、[06-online-match-wireframe.md](ui-reference/06-online-match-wireframe.md)。本報告其餘章節（§2–4）仍反映當時觀察，尚未逐一重新驗證。

## 1. 主選單：無自訂牌組時主 CTA 與下一步可理解性

> **已解決**（2026-07-11）：無自訂牌組時「建立第一副牌組」現為主 CTA，「對戰入口」disabled 並顯示原因文字；有牌組時還原「對戰入口」為主 CTA。實機 1280×720 驗證（accessibility tree + computed grid layout）與 15 項單元測試（`OnlineMatchPanel.test.tsx` 為線上面板，主選單空狀態另有既有測試覆蓋）通過。詳見 [Wireframe 02](ui-reference/02-main-menu-wireframe.md)。

### 本機 1280×720 截圖已觀察

- 主選單以大標題「Braverse」開頭，下方為三段式垂直佈局：快速開始、牌組編輯器、設定/離開。
- 「快速開始」列直接顯示兩組預設 Starter Deck（Red/Yellow）按鈕；無自訂牌組時此區為空列或僅顯示預設選項。
- 無自訂牌組時，尚無明確引導玩家前往「建立牌組」的視覺線索，主 CTA 分散在「快速開始」的預設牌組與下方較小的「牌組編輯器」文字之間。
- 頁尾版權文字對比偏低（`rgba(210,226,252,.55)`），與背景融合，但不影響主要操作。

### 後續假設

- 推測玩家首次進入時應以「牌組編輯器」為優先落點，而非直接快速開始。
- 推測牌組編輯器空狀態應提供「建立新牌組」或「匯入範例牌組」的明顯入口。
- 推測主選單需一致的主 CTA 層級：無自訂牌組時放大「牌組編輯器」入口，存在自訂牌組時以「快速開始」為首選。

## 2. 牌組編輯器：卡池與右側摘要資訊層級

### 本機 1280×720 截圖已觀察

- 牌組編輯器左側為卡池（CardPool），以網格呈現可選卡牌；右側為牌組摘要（deck summary）與目前牌組清單。
- 卡池卡片以縮圖 + 名稱呈現；顏色過濾與搜尋功能標示但尚未完整樣式化。
- 右側摘要顯示牌組卡片數量、顏色分佈比例；資訊層級扁平，無「下一步儲存/測試/分享」的明確出口。
- 卡池卡片與已加入牌組卡片之間的拖放或點選新增回饋尚無明確視覺變化。

### 後續假設

- 推測卡池搜尋/過濾功能需完成樣式化後，才能準確評估資訊層級。
- 推測右側摘要區應增加「儲存牌組」、「測試對戰」等出口按鈕，並以色彩區分優先級（儲存為主 CTA、測試為次要）。
- 推測牌組編輯器的卡片詳情放大預覽（W1 全域放大）在此處特別重要，因卡池卡牌尺寸小。

## 3. 測試對局設定：雙方欄位可讀性

### 本機 1280×720 截圖已觀察

- 對局設定（game setup）頁面以雙欄呈現：左欄玩家 1（我方）、右欄玩家 2（對手/測試對象）。
- 雙方欄位包含牌組選擇下拉、名稱輸入、AI 類型選擇；下拉清單樣式與既有的深藍半透明面板一致。
- 1280×720 下雙欄無重疊，可清楚辨識雙方設定。
- 「開始對戰」按鈕位於底部居中，醒目且明確。

### 後續假設

- 推測欄位在更窄視窗（<900px）下需改為上下堆疊，可能影響操作效率但非優先。
- 推測目前無「載入儲存牌組」的直接入口（需先於牌組編輯器儲存），此為功能面缺口而非純 UI 問題。

## 4. 對局桌面：資訊密度與空白區

### 本機 1280×720 截圖已觀察

- 戰場滿版無捲軸，上區為對手場地、下區為我方場地；中央分隔列為攻擊/付款/目標選擇提示區。
- 戰鬥區（55%）與支援區（45%）固定比例；手牌扇形位於底部我側。
- 我方場地資訊密度適中：戰鬥卡放大可讀、支援卡併排可辨、能量/牌庫/休息區數字清晰。
- 對手場地資訊密度偏低：對手卡牌以縮小背向顯示，僅 hover 時可窺見部分資訊；對手支援區卡牌尺寸小且無快速放大途徑（此即 W1 改進項）。
- 中央分隔列在無攻擊/效果進行時為大片空白，約占畫面 15-20% 高度區塊。
- PhaseRail 左側窄列佔用約 5% 寬度，五階段垂直排列於此。

### 後續假設

- 推測中央空白區可動態利用：對手出牌時顯示卡牌放大預覽、技能發動時顯示效果摘要。
- 推測可考慮縮減中央空白區高度（從 15-20% 降至 10-12%），將空間還給戰鬥/支援區，或保留為效果提示專用區。
- 推測 W1（全域卡牌放大預覽）完成後，對手場地可讀性問題會部分緩解。

## 5. 線上對戰彈窗控制項重疊 / 未樣式化（P0）

> **已解決**（2026-07-11）：`OnlineMatchPanel.tsx` 改版為 `.online-match-panel` 專屬樣式（32×32px 關閉按鈕、內容區捲軸管理、完整 hover/focus-visible/active/disabled 狀態），且目前版式無房間列表（改為「建立房間」／「輸入房號加入」兩個並列動作），原本的列表重疊問題不再適用。15 項單元測試涵蓋 idle/waiting/error/close/dialog/label/connecting 路徑。詳見 [Wireframe 06](ui-reference/06-online-match-wireframe.md)。

### 本機 1280×720 截圖已觀察

- 線上對戰（online match）彈窗以深色置中 modal 開啟，包含大廳列表、建立房間、加入房間三個區塊。
- **P0-1 控制項重疊**：大廳列表與「建立房間」按鈕在 1280×720 下，當列表含多個房間時，「建立房間」按鈕與最後一個房間項目垂直重疊。
- **P0-2 未樣式化**：房間列表項目僅有文字，無邊框/背景/hover 效果；加入按鈕無明顯區隔，與房間名稱擠在同一行。
- **P0-3 彈窗尺寸**：modal 寬度固定，但內容區高度無捲軸管理，房間數量多時內容溢出。
- 線上對戰設定區（牌組選擇、房間密碼輸入）控制項排列擁擠，label 與 input 之間無間距節奏。
- 關閉按鈕（X）位於右上角但尺寸偏小（約 20×20px），hover 區域不足。

### 後續假設

- 推測這些問題源自線上對戰功能快速迭代期間，UI 未經過設計審查即合併。
- 推測修復優先級為 P0（阻擋基本可用性），應在 W 系列改進項之前獨立處理。
- 建議方案：列表加捲軸容器與固定高度、項目加卡片式邊框/背景與 hover 效果、按鈕與文字分離成兩行或左右配置、關閉按鈕加大至 32×32px 以上。需以 1280×720 與 1366×768 兩解析度驗證不重疊。
